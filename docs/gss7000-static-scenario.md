# GSS7000 / SimREPLAYplus 静态 GNSS 场景配置与现场核验

> 适用范围：本项目 GSS7000 + SimREPLAYplus 6.00.02，兼顾后续 10.02.00。本文是**现场操作清单**，不是未经核实的逐按钮官方菜单教程。具体菜单名称、许可证能力和场景文件生成方式须以现场 SimREPLAYplus 版本及授权手册 DGP01449AAA 为准。不要把 SimGEN、SimTEST 的界面操作照搬到 SimREPLAYplus。

## 一、目标与关键区别

建立一个**位置固定、速度为零、时间及卫星信号可重复**的 GNSS 场景，供 Android 手机在屏蔽箱内验证捕获、TTFF、定位误差和灵敏度。

- **静态**指模拟接收机位置随场景时间不变，并不表示卫星位置不变。卫星仍随时间运动。
- **场景文件**与**场景播放**是两步：如果 SimREPLAYplus 只支持加载和回放预生成场景，须先由现场授权的场景制作工具或厂家提供静态场景文件；不要假设 SimREPLAYplus 能直接编辑轨迹、星历或生成文件。
- **仪表功率设置**不等于手机显示的 C/N0（dB-Hz），也不等于手机天线端的实际 dBm。

## 二、现场准备

1. 确认 GSS7000 型号、SimREPLAYplus 版本（已验证现场为 **6.00.02**）、许可的星座/频点及场景文件格式。
2. 连接 GSS7000 GNSS RF → 适当衰减/滤波/屏蔽箱穿墙口 → 箱内天线或经授权的 DUT RF 输入；核实线损、耦合、功率上限与屏蔽效果。**禁止在开放环境辐射模拟 GNSS 信号。**
3. Windows 控制机与 GSS7000 建立 LAN 连接；避免两个控制客户端同时修改场景。
4. 选择测试手机、固定姿态；关闭会引入真实 GNSS 信号的箱门缝隙，确认 ADB 穿墙 USB 连接不破坏屏蔽。
5. 确认是否需要 LTE/A-GPS：GNSS_ONLY 可无蜂窝基站；若要测试 A-GPS，另行配置受控网络、辅助数据和启动条件，不能把“插卡”直接等同于“已获得 A-GPS”。

## 三、静态场景的参数清单（创建/申请场景文件时填写）

| 参数 | 建议与核验方式 |
| --- | --- |
| 场景类型 | Static / Stationary / Fixed receiver（以现场工具的真实名称为准） |
| 接收机位置 | 选定一个**明确的 WGS84 纬度、经度及高度**；测试程序的 reference 必须与场景一致 |
| 速度、轨迹 | 速度 0，整个观察期间位置不变化；不添加运动路径 |
| 起始 UTC 日期与时间 | 记录实际配置；避免与手机当前辅助信息发生未记录的冲突 |
| 场景时长 | 覆盖功率稳定等待、每轮 TTFF 观察、重复试验及场景重启所需时间 |
| 星座、频点 | 以手机能力、GSS7000 选件和本轮测试目标为准；先用单一明确配置建立基线 |
| 星历/导航电文 | 使用与场景 UTC 一致的有效星历；由生成工具或场景提供方确认 |
| 可见卫星与几何 | 检查场景参考位置的卫星可见数、几何分布；不要以手机显示数量反推场景文件已正确 |
| 信号功率 | 明确仪表的参考对象、设置值、端口、线损、天线耦合和参考平面 |
| 传播与干扰 | 首轮基线关闭不必要的遮挡、衰落、多径、干扰；后续按独立场景引入 |
| 场景标识 | 记录文件名、仪表上的完整路径、版本、生成工具、校验哈希与参数表 |

**注意：**这里没有指定“北京/东京某坐标”或任意默认日期，因为测试参考位置和模拟 UTC 必须由现场真实场景确定；随意填写会使水平误差、辅助定位与星历判断失去意义。

## 四、按上午讨论的菜单路径配置静态场景（待现场核实）

> **重要：以下是上午讨论的拟操作路径，尚未通过现场 SimREPLAYplus 6.00.02 菜单截图或授权手册逐项验证。** 特别是 `PosApp`、`Circular motion file → Static`、`File → New` 和 `File → Save As` 的存在、层级及适用版本都待确认。不要把它们当成已经实测的 V6 操作说明；如果找不到对应入口，不要尝试用不相干的菜单代替。

### A. 创建/打开场景

1. 在 GSS7000 控制电脑打开 **PosApp / SimREPLAYplus**（先核对实际窗口名称和版本）。
2. 按上午讨论的路径尝试 **`File → Open Scenario`**，打开已有场景；如果需要从零创建，核查软件中是否有 **`File → New`**。
3. 若 V6 只有场景加载/回放功能，没有编辑入口，则停止此流程：改用现场授权的场景生成工具（例如具有相应许可的 SimGEN）制作静态场景，再由 SimREPLAYplus 加载。**不能把加载成功视为已经创建了静态场景。**

### B. 设置接收机静止位置

1. 在场景树中寻找 **`Vehicle 1 → Motion → Circular motion file`**（此名称及路径待核实）。
2. 如果实际界面提供 **`Static`** 或等价的固定位置模式，选择该模式；若没有，记录真实菜单和截图，不能假设 Circular motion 本身就是静态。
3. 输入固定位置的 **Latitude（纬度）**、**Longitude（经度）**、**Altitude（高度）**；核对坐标基准为 **WGS84**、角度正负号和高度参考。
4. 确认整段场景接收机速度为 **0**、轨迹位置不变；不添加圆周运动、速度变化或路线文件。将这组经纬度同步填写到本项目上位机的 reference 字段。

### C. 设置 GNSS 信号和卫星

1. 在场景树中寻找 **`Vehicle 1 → Antenna 1 → Signal types`**（待核实）。
2. 初次联调按仪表许可和手机能力选择 **`GPS L1 C/A`**；先建立单星座基线，再按需要增加其他星座和频点。
3. 检查 **`GPS constellation`**（待核实）的卫星可见性、导航数据及场景时间匹配；避免把“勾选了卫星”直接理解为“手机一定参与定位”。
4. 在软件实际提供的时间设置中配置 **`Start time`**（UTC）和 **`Duration`**（覆盖完整试验时长）；核对星历/导航电文与该时间相容。

### D. 保存、加载和运行

1. 如果当前软件支持编辑与保存，尝试 **`File → Save As`**，另存为新静态场景；记录文件路径、格式及哈希。**不要覆盖已有验证场景。**
2. 在 SimREPLAYplus 中停止当前回放，再加载新场景；确认原厂界面显示的场景名称、位置和信号类型（如果可见）。
3. 设置批准的安全基准功率；在现场 V6 使用经核实的 `POW_LEV` / `v1_a1` 适配流程，并通过原厂界面人工核对。
4. 启动回放，确认状态变为运行；将手机放入屏蔽箱，先验证新鲜 GPS fix、坐标与卫星遥测，再进行弱信号测试。
5. 保存场景配置截图、仪表日志和手机 GNSS 原始数据。

### E. 现场菜单核实表

| 待核实入口 | 上午讨论的名称 | 实际菜单 / 结论 |
| --- | --- | --- |
| 软件主界面 | PosApp / SimREPLAYplus | 待填 |
| 新建场景 | File → New | 待填 |
| 打开场景 | File → Open Scenario | 待填 |
| 静态运动模式 | Vehicle 1 → Motion → Circular motion file → Static | 待填 |
| 卫星信号类型 | Vehicle 1 → Antenna 1 → Signal types | 待填 |
| 星座 | GPS constellation | 待填 |
| 场景时间 | Start time / Duration | 待填 |
| 保存 | File → Save As | 待填 |

如果上述任一入口不存在，应记录 **V6.00.02 的实际菜单截图**及场景文件来源，优先判断是否属于 SimGEN 场景编辑功能，而非继续猜测菜单。

## 五、SimREPLAYplus 现场加载及播放步骤

1. 在仪表控制机打开 SimREPLAYplus，确认当前软件版本及仪表就绪。
2. 如现场版本有场景生成/编辑入口，依据第三、四节参数及待核实菜单创建静态场景；**如无该功能**，使用已经生成并经过核验的静态场景文件。
3. 将场景文件放到仪表可访问的位置，记下**仪表侧完整路径**。不要把上位机 Windows 本地路径误当成仪表路径。
4. **停止**当前播放，加载静态场景；在原厂界面核对当前场景名称/路径和参考位置（若界面提供）。
5. 设置经过批准的基准 RF 功率，核对原厂界面显示；不要直接开始极弱信号扫描。
6. 启动场景，观察原厂界面确实处于运行状态，等待输出稳定。
7. 先在相对较强且安全的基准信号下，让手机在屏蔽箱内验证新鲜 GPS fix、坐标、TTFF、可见卫星和参与解算卫星数。
8. 连续停止/重启场景，核实可重复；保存截图、命令日志、手机原始遥测及场景哈希。

**本项目已核实的远控事实（V6）：** TCP 端口 **15650**；停止/复位后状态 **2**，启动过程使用 `TR,0` 后 `RU`，运行状态 **5**。场景加载、启动、停止与原厂界面一致性曾经通过现场验证。V6 的功率设置使用 `POW_LEV`，对象 **`v1_a1`**（vehicle 1 antenna 1），而不是 `v1`；具体完整命令格式以当前项目适配器和现场手册为准。**V6 不支持已验证的远程功率读回**，原厂界面确认属于人工证据，不能冒充 RF 测量读回。V10 相关命令尚未完成实机验证。详见 [阶段二验收记录](stage-2-gss7000-validation.md)。

## 六、与本项目上位机联动

1. 先在 **GSS7000 调试**界面连接，版本选择 **V6.00.02**，填现场地址、15650、实际终止符和 XML 响应格式。
2. 读取仪表状态及当前场景，停止后加载第五节确认的静态场景文件。
3. 启动并确认运行；设置批准范围内的功率，核对原厂界面。现场 V6 的 `POW_LEV` 是 **GPS vehicle 1 antenna 1 的参考 dB 设置**，**不是** DUT 天线口的绝对 dBm。
4. 在上位机填写与场景一致的参考经纬度、启动模式、观察窗口和场景标识；准备手机并执行一次闭环采集。
5. 正式 P4 固定功率和 P5 逐档扫描前，核对功率参考平面与校准证据。若无法证明真实功率读回，按项目验收约束采用人工核验或暂停正式自动判定，**不要把“设置成功”当作“读回成功”**。
6. 每档保存：场景路径与哈希、版本、功率设置、原厂截图、GNSS 原始回调、首次 fix 时间、TTFF、C/N0、used-in-fix、状态与失败原因。

## 七、常见问题与排查

### 手机 C/N0 只有 20 多 dB-Hz，定位困难

先确认手机显示的是 **C/N0（dB-Hz）**，而非仪表 dB 衰减。用较强且经批准的基准信号验证完整闭环，再逐级减弱；检查 RF 路径损耗、场景可见卫星、星座/频点、时间和星历是否一致。20 多 dB-Hz 时导航电文解码和首次捕获可能困难，但不能仅凭该数值断言仪表配置错误。

### 室外插卡可定位，屏蔽箱内无法定位

分别比较 GNSS_ONLY、自主定位、预先获取辅助信息、箱内受控联网条件。核查模拟位置/时间与手机缓存的辅助信息是否冲突。**HOT 测试不得通过先启动 GNSS 定位来人为缩短 TTFF**；预热只能作为独立记录的实验条件，不能混入正式计时。

### 可见卫星不少，但 used-in-fix 为 0

可见、跟踪、参与解算是不同指标。保存每颗卫星 C/N0、星座、SVID、usedInFix、定位回调与单调时钟时间。Android 两类回调不同步；本项目使用有时间容差的定位后卫星回调关联，属于**近邻遥测证据**，并非严格证明首次 fix 瞬间的卫星集合。

### 场景运行正常，但自动化判定 INVALID

先看 `ATTEMPT_RESULT` 的 `reason`，区分 GNSS 未就绪、首次 fix 缺失、卫星状态回调缺失、USB 断开、功率未核验等。**INVALID 不等于灵敏度 FAIL**，不能通过删除证据检查来强制判 PASS。
