# P1–P5 现场逐项验收测试用例（执行记录表）

> 版本：2026-11-25；目标分支 `codex/phase-1`。此文件为**人工现场验收表**，不是已执行的测试报告。所有“实际结果”由现场填写；禁止提前标 PASS。P6 尚未开发，不纳入本次交付验收。

## 0. 统一填写方法

每条测试都按“前置条件 → 操作步骤 → 预期结果 → 实际结果 → 判定”执行。复制本文件作为现场记录副本；原版用例保持不变。

**执行环境**：日期：____；执行人：____；Windows/上位机版本：____；Git commit：____；Android 型号/系统：____；APP 版本：____；GSS7000 型号/SimREPLAYplus 版本：____；CMW500 固件/LTE 选件：____；USB 序列号：____；校准记录：____；GNSS 场景及哈希：____；场景参考 WGS84 经纬度：____；RF 参考平面：____。

**判定**：PASS=现场结果满足全部预期；FAIL=不满足；BLOCKED=缺设备、权限、校准或前置条件；N/A=经批准不适用（须写原因）。测试失败须记录日志路径、错误信息、复现步骤及修复后复测结果。测试失败不可修改判定阈值来“通过”。

**每项记录模板**：`用例ID | 执行时间 | 实际结果 | PASS/FAIL/BLOCKED/N/A | 证据文件/截图 | 问题单/备注`。每个阶段单独签字：____。

### 共同安全前置条件
1. GNSS/LTE RF 仅在合规屏蔽环境运行；确认连接器、线损、衰减器、DUT 输入和允许功率，核对 CMW 小区是否原本开启。
2. 真实测试禁用 mock；测试场景、经纬度、校准范围和外部功率证据真实有效。**V6 的 `POW_LEV` 是参考 dB，不是 dBm**；单点校准不能证明整个扫描范围。
3. 先分别验收 P1/P2/P3，再运行 P4/P5。每次异常后检查手机、GSS、CMW 的最终实际状态。
4. 对异常注入（断线、关闭仪表）先停止 RF 或在授权安全条件下操作，勿在运行中随意插拔射频线缆。

## P1 — Android USB GNSS 独立采集

| ID | 前置条件和操作步骤 | 预期结果与核验点 |
|---|---|---|
| P1-01 | 安装 Android APP，授予精确定位权限并开启定位服务；启动采集服务 | 上位机可检测到设备；APP 显示服务就绪 |
| P1-02 | USB 调试已授权；连接单台手机，选择正确序列号 | ADB 可连接，设备标识一致；不误连其他手机 |
| P1-03 | 进入 USB 调试页，执行 HELLO、PING、GET_STATUS | 返回 ready、instance_id、活动试验状态；请求与响应正确关联 |
| P1-04 | CONFIGURE_RUN，使用真实 run_id，核对 ACK | APP 接受配置；run_id 不混用旧任务 |
| P1-05 | PREPARE_ATTEMPT（HOT）并提交非空准备证据 | 进入已准备状态；空证据拒绝 |
| P1-06 | START_ATTEMPT，观察首次定位、卫星回调和 ATTEMPT_RESULT | 返回新鲜的单调时钟 t0/first_fix、经纬度、used_in_fix、关联信息；非 mock |
| P1-07 | 现场人工比对首次定位时间、TTFF、参考经纬度与 APP 原始记录 | TTFF=(first_fix_elapsed_realtime_ns−t0_monotonic_ns)/1e9；经纬度与原始事件一致 |
| P1-08 | 连续执行 3 次独立 HOT 尝试 | 每次独立 attempt_id、单调时钟起点；结果不复用上一轮 |
| P1-09 | 正在采集时 STOP_ATTEMPT，随后 STOP_RUN | 活动试验终止；停止后的状态可查询；无残留活动试验 |
| P1-10 | USB 连接中断后重新连接并查询 | 明确报通信错误；不把旧结果当新结果；恢复后能重新建立会话 |
| P1-11 | 关闭定位权限或定位服务再执行 | ready 变为 false 或拒绝；不可生成虚假 PASS |
| P1-12 | 重复 ACK/旧 attempt_id/旧事件重放（使用调试/自动化脚本） | 不重复计入有效试验；有可追踪的错误或去重证据 |
| P1-13 | 触发超时（安全环境中屏蔽 GNSS），等待观察窗口结束 | 真实超时按协议区分 FAIL/TIMEOUT 与 INVALID/GNSS_NOT_READY |
| P1-14 | 退出、重启 APP/上位机，再查询状态 | 不静默继承未结束任务；能核对实例 ID 和审计日志 |

**P1 必留证据**：USB 调试命令日志、APP 日志、至少 3 次原始 ATTEMPT_RESULT、一次取消/超时记录。

| P2-02 | 断开连接再打开软件 | IP/端口与场景路径恢复；不需要重复录入 |
| P2-03 | 加载指定场景（现场真实路径），查询状态 | 加载成功，原厂界面与上位机显示一致 |
| P2-04 | 启动场景，查询运行状态；随后停止 | 运行、停止状态与原厂界面一致；不残留 RF 输出 |
| P2-05 | 核对场景参考经纬度、信号类型和起始时间 | 与场景文件/原厂界面一致；不使用合成参考坐标 |

| P2-08 | V10.02.00 环境（如有）设置 `POW_LEV,v1` 并按版本查询 | 指令对象匹配对应版本；若无 V10，记 N/A |

| P2-10 | 在已校准范围内改变 1 dB，独立核对 RF 实际变化 | 变化符合现场批准容差；异常时禁止进入 P5 |
| P2-11 | 场景加载失败、IP 错误、端口拒绝或超时 | 明确失败；不标记运行成功；能人工恢复 |
| P2-12 | 场景运行中执行停止或关闭软件前安全停止 | 原厂界面确认场景停止；记录状态 |
| P2-13 | 同一场景启动/停止连续 3 轮 | 无遗留状态；每轮状态及日志可核对 |

**P2 必留证据**：版本、场景、状态截图、V6/V10 指令日志、外部功率校准记录及 1 dB 变化核验。

## P3 — CMW500 LTE 独立控制

| ID | 前置条件和操作步骤 | 预期结果与核验点 |
|---|---|---|
| P3-01 | 配置 CMW IP/端口（TCP SCPI 默认 5025），查询 *IDN?、BASE 版本及选件 | 返回真实 CMW500 身份与版本；若现场只支持 VISA，记录 BLOCKED/待适配 |
| P3-02 | 读取当前 LTE 双工、Band、EARFCN、带宽、RS EPRE、RF 路由 | 上位机读值与原厂界面一致 |
| P3-03 | 小区 OFF 时按现场批准组合设置 Band/EARFCN/带宽/双工 | 写入成功并读回一致；非法组合不得伪报成功 |
| P3-04 | 设置 RS EPRE，读取并恢复 | 与原厂一致；不将 RS EPRE 当总发射功率 |
| P3-05 | 选择 COM1～COM4 中现场真实 RF 端口，配置路由 | 实际路由、接线、读回一致；不自动猜测端口 |
| P3-06 | 配置 INPut/OUTPut 外部衰减（线损） | 与校准值一致；读回符合设定 |
| P3-07 | 执行 LTE 初始化：UE Report、MAXP、P-Max、RMC、安全配置 | 无 SCPI 错误；现场核对原厂配置；记录具体固件差异 |
| P3-08 | 启动小区并查询 `SOURce:LTE:SIGN:CELL:STATe?` | 返回 ON；原厂界面确认 RF 小区开启 |
| P3-09 | 手机执行真实 LTE 注册，原厂界面核对 NAS 注册 | NAS 注册成功且有独立证据；不能只凭 CELL ON 或 RRC CONN |
| P3-10 | 查询 `SENSe:LTE:SIGN:RRCState?` 并等待 CONN | 已连接时 CONN；200ms 轮询，最长 30 秒 |
| P3-11 | 不连接手机，等待 RRC 连接超时 | 明确超时，不伪造连接成功 |
| P3-12 | 停止小区并读回 | OFF；原厂界面确认 RF 状态 |
| P3-13 | 完成 3 轮“小区启动→手机连接→停止” | 每轮连接状态真实；无旧状态污染 |
| P3-14 | CMW 网络断开或 SCPI 返回错误 | 记录错误，不盲目重发射频配置；恢复后可重新读取 |
| P3-15 | 软件重启后检查 IP/端口、COM、线损配置 | 配置自动保存；不会误将旧的现场状态视为已验证 |
| P3-16 | 原本已开启的小区进入 P4/P5，再停止测试 | 不擅自关闭原有小区；由现场人员核对最终 RF 状态 |

**P3 必留证据**：CMW SCPI 日志、原厂 NAS/RRC 截图、LTE 配置和 RF 路由/线损记录、超时与停止日志。

## P4 — 固定功率 −120 dBm，20 次有效定位

| ID | 前置条件和操作步骤 | 预期结果与核验点 |
|---|---|---|
| P4-01 | P1–P3 通过；打开“P4 / P5 联合测试”页 | GUI 正常；GSS/CMW/USB 参数可填写并保存 |
| P4-02 | 输入真实场景、经纬度、校准测量 dBm、对应参考 dB、有效范围及证据 | 完整且合法；校准缺失或目标 -120 dBm 超范围时拒绝启动 |
| P4-03 | 输入非法 IP/端口、无效经纬度、空场景或空校准编号 | 明确提示错误；不得启动真实测试 |
| P4-04 | 点击“开始 P4 固定 20 次”并确认 RF 安全提示 | 预检三设备、确认 LTE RRC、GSS 场景和 -120 dBm 目标 |
| P4-05 | 独立核验 RF 实际功率并填写证据 | 功率确认后才开始 GNSS 轮次；取消/空证据应停止 |
| P4-06 | 连续完成 20 次有效 HOT 定位 | 每轮有独立 attempt_id、手机原始遥测；每轮前后核对 RRC 和 GSS |
| P4-07 | 对照手机日志逐轮核算 TTFF、水平误差、used_in_fix | TTFF ≤20.3s、水平误差 ≤101.3m、卫星 ≥4 才为 PASS |
| P4-08 | 20 次中恰好 19 次 PASS、1 次 FAIL（可用软件受控测试数据验证边界） | 整组 PASS，成功率 95%；**软件边界测试不得冒充真实 RF 结果** |
| P4-09 | 20 次中 18 次 PASS、2 次 FAIL（受控软件测试） | 整组 FAIL，成功率 90% |
| P4-10 | 注入连续 1～2 次 INVALID（受控软件测试） | INVALID 不计入 20 次有效样本；允许额外重试 |
| P4-11 | 注入连续第 3 次 INVALID（受控软件测试） | 暂停，记录错误，不生成虚假 PASS |
| P4-12 | 运行中让 LTE RRC 断开（安全条件下） | 当前轮不得计入有效；测试暂停；记录原因 |
| P4-13 | GSS 功率/运行状态异常或独立功率证据取消 | 不继续计数；安全停止；记录设备错误 |
| P4-14 | 手机 USB 断开、超时或 APP 不就绪 | 暂停或按协议标 INVALID；不将通信错误记为 GNSS 灵敏度 FAIL |
| P4-15 | 运行中点击“取消并安全停止” | STOP_RUN、GSS 停止、程序拥有的 CMW 小区关闭；若未确认安全停止则报告 PAUSED |
| P4-16 | 正常结束后点击“打开本次报告” | 生成 `fixed.json`、`phone_audit_*.sqlite`、`report.csv`、`report.html`；数据逐轮一致 |
| P4-17 | 再次启动新的 P4 测试 | 新 UUID 目录；历史结果不覆盖 |
| P4-18 | 正在测试时尝试关闭软件或启动另一个仪表任务 | 拒绝并发/安全请求停止；不出现两个任务同时控制仪表 |

**P4 必留证据**：20 次原始结果、逐轮判定表、功率证据、LTE 连接记录、报告文件、异常注入至少 1 次。

## P5 — GNSS 灵敏度逐档扫描

| ID | 前置条件和操作步骤 | 预期结果与核验点 |
|---|---|---|
| P5-01 | P4 通过；设置最低 -122 dBm、最大 3 档；校准范围覆盖全部档位 | 参数校验通过；软件不会越过校准范围 |
| P5-02 | 点击“开始 P5 逐档扫描” | 从 -120 dBm 开始，下一档 -121、再下一档 -122，每档下降 1 dB |
| P5-03 | 核对每档 GSS `POW_LEV` 参考值与外部校准证据 | 目标 dBm 与参考 dB 换算正确；各档 RF 变化有独立证据 |
| P5-04 | 首档完成 20 次有效 HOT 定位 | 每档单独预检、启动、20 次判定和安全停止；记录独立档位文件 |
| P5-05 | -120 档 ≥19/20 PASS | 继续到 -121 档 |
| P5-06 | -121 档 ≥19/20 PASS | 继续到 -122 档；此前通过档保留 |
| P5-07 | -122 档首次不足 19/20（受控数据验证） | 扫描停止；灵敏度阈值记最后通过的 -121 dBm |
| P5-08 | -120 首档不足 19/20（受控数据验证） | 立即停止；阈值为 null/无，不得填 -120 |
| P5-09 | 最低功率或最大档数到达且全部通过 | 正常停止，原因 MIN_POWER_REACHED 或 MAX_LEVELS_REACHED；记录最后通过档；**不能声称已找到首次失败边界** |
| P5-10 | 中途某档出现连续第 3 次 INVALID | PAUSED，保留此前通过档和当前异常；不把异常档记 FAIL |
| P5-11 | 中途 LTE RRC 丢失、GSS 失联或 RF 校准证据不足 | PAUSED；保留历史数据；不继续降功率 |
| P5-12 | 运行中点击取消 | STOPPED 或在安全停止失败时 PAUSED；已测档数据不丢失 |
| P5-13 | 某档 20 次结束后检查 USB 会话、GSS 状态、CMW 小区 | 该档资源被清理；下一档不会复用旧 attempt_id/旧结果 |
| P5-14 | 检查 `sweep.json`、各档 `level_<dBm>.json`、CSV/HTML 和手机 SQLite | 档位、20 次记录、PASS 数、阈值及停止原因一致 |
| P5-15 | 复用已有非空结果目录 | 拒绝覆盖；生成新的 UUID 目录 |
| P5-16 | 输入最低功率 > -120、最大档数为 0/超过 200、校准范围不覆盖扫描 | 明确拒绝启动；不能悄悄截断或使用默认校准 |
| P5-17 | 实测与报告的功率值比较 | 明确区分“目标 dBm”“发送的 POW_LEV 参考 dB”“外部测量证据”，不能把命令成功当成测量成功 |

**P5 必留证据**：完整 `sweep.json`、至少两个档位的 20 次结果、每档外部 RF 功率证据、首次失败停止或范围结束的证明、HTML/CSV 报告。
