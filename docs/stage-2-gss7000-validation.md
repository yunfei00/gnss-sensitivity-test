# 阶段二：GSS7000 独立远控调试

本阶段先交付可配置 TCP 指令工作台，不预设仪器命令、端口、功率单位或响应格式。现有正式测试引擎仍使用人工仪器确认。

## 使用
更新分支后运行 uv run --locked python -m desktop，打开 GSS7000 调试。填写现场远控 IP、端口及发送/响应结束符。当前每条指令独立 TCP 连接，若手册要求长连接、握手、长度帧或 XML 流，需要进一步适配。先用只读指令验证。选择操作，输入模板并保存到本机 QSettings；场景和功率使用 {value} 参数。也可发送单条原始指令。所有发送均须确认；无响应不代表执行成功，不自动重试。日志在页面查看。

## 请从现场手册确认
- TCP 服务启用、端口、连接方向、是否长连接、握手、编码、请求/响应结束符或长度帧。
- 型号、软件版本、状态查询指令及完整响应例子。
- 当前场景查询、加载场景、启动、停止及状态读回。
- 功率设置、读回、单位（绝对 dBm 或相对 dB）、参考值、信号范围、合法区间。
- 错误响应、执行完成条件、RF 关闭验证。

先验证只读，再在屏蔽条件下验证场景及功率。不得以 TCP 成功代替 RF 读回。阶段一补验首次新鲜定位、TTFF、最终解算卫星数。未定位时查看 ATTEMPT_RESULT 的 status/reason，不以采集结束判定成功。

## 内置指令试用版
默认端口 15650，XML 完整帧读回，发送结束符 LF 为待实机验证的可修改初值。先启用 BSD sockets，查询状态和型号，再加载场景、选择软件触发、启动、查询运行状态、停止并复查状态。功率模板仅为 GPS vehicle 1 的参考 dB 调整试用项，不能视为手机端绝对 dBm，其他星座及实际功率读回需现场配置核验。原始指令及模板可修改；不得自动重发超时指令。正式测试引擎不变。手册不纳入仓库。
